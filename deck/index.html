01

First, what a CDN is.

It keeps copies of content close to you, and picks the fastest route to one. Cloudflare does it from ~330 cities. Every one of them is bolted to the ground.

Without a CDN
Your request travels to one distant origin server. Twelve thousand kilometres. Everybody waits.
With a CDN
Your request stops at the nearest edge node. Three hundred kilometres. The map never moves.
In orbit
The map is the variable.
Nodes move
7.5 km/s. The nearest node is different by the time you finish reading this.
Nodes go dark
Eclipse. A solar-powered data centre on battery is a data centre you should route around.
Packets corrupt
South Atlantic Anomaly. Single-event upsets where the Van Allen belt dips low.
The door closes
Rain. Ka-band fade shuts the ground gateway your request has to come down through.

Which orbital data centre serves this request, right now — given that it is eclipsed, crossing the anomaly, and its downlink gateway is in rain?
THE STANDARD OBJECTION
LEO adds round-trip delay, Doppler shift and handover cost — so orbit suits AI training and batch work, not latency-sensitive inference.
That objection is a routing problem.
So we built the router, and measured it.
04

One currency: milliseconds.

Sunlight, radiation and rain are not thresholds to trip. They are costs to trade against distance.

C(DC) = w_lat·reachMs + w_sol·25 ms·S + w_rad·40 ms·R + w_lat·18 ms·Plat + w_rad·18 ms·Prad
C(G)  = w_lat·reachMs + w_wx·W + w_wx·18 ms·PG + w_wx·F
// S eclipsed · R in the anomaly · W rain fade 0/8/22 ms · F P(outage)×900 ms
// P learned from observed telemetry over the selected window
That single unit is what makes four routing policies the same engine with different weights — latency, balanced, reliable, green — instead of four hand-written special cases.

06

It learns from its own history.

Select a period. The network summarises what actually happened over exactly that window — and the penalties it derives feed straight back into the next routing decision.

User-facing behaviour
1H · 24H · 7D · 30D · ALL
Every KPI, every breakdown and the chart's bucket granularity recompute for the selected window. 1H → 1 request · ALL → 995
Derived patterns
Which gateway lost time to rain. Which data centre ran eclipsed. Which policy won, per origin. Eight rules, written in prose.
Product state
An append-only event log — 20 fields per served request — aggregated into gateway, latency and radiation penalties.
The loop closes
Those penalties are read inside the cost function. Not a dashboard bolted on beside the product — the summary changes the next route.
And it stays honest
Too little traffic in a window? It widens and says so. Recommendations are surfaced, never auto-applied — the policy you chose keeps meaning what it says.

08

Grounded against sources we don't control.

Rain attenuation
ITU-R P.838-3 / P.618-13 / P.839-4 implemented from the published standard. 28 of 28 coefficients validated to within 2% — as a unit test in the repo.
Orbital mechanics
SGP4 propagation of 180 satellites from live CelesTrak TLEs. Not a decorative animation.
Fibre baseline
Measured WonderNetwork inter-VPS RTT, cross-checked against Microsoft Azure's published P50 backbone medians. Datacentre-to-datacentre, so it understates our advantage.
Weather
NASA POWER hourly precipitation. Four months, eight gateway sites.
And the bound we don't hide: across four months only one of eight gateways exceeds the 6 dB link margin, in 19% of its hours. The benefit of any weather-aware routing is bounded above by that exposure — we say so in the product.
